报名、组队和作品提报通过官方活动页面完成，详细规则以官方开发者手册及后续通知为准。

- 面向参赛者的详细说明：[S3 开发者手册](https://pcnsiq9mmnww.feishu.cn/wiki/W1DVwHiJSigXq1k6ys7cHTuOnBe)。

报名后按活动页面和官方助手指引进入组队、建项及提报流程。

报名需要登录知乎账号，按页面要求提交信息。报名成功后添加官方助手并加入社群，以获取赛事通知、技术答疑和组队信息。

## 参赛条件与赛道

参赛对象：国内外在读学生（初高中、专本科、硕士、博士），以及毕业不超过 3 年的职场新人。

支持单人或团队参赛，每队 1–5 人，允许跨校、跨专业组队；每人仅可加入 1 队，每队限提交 1 个作品。开发与作品提交全程线上参与，决赛路演支持深圳线下或线上连线。

项目提交时选择以下赛道之一，作品必须与赛道主题及知乎社区生态相关：

| 赛道 | 目标与作品方向 |
|---|---|
| AI × 知识与探索 | 基于知乎问答与多元观点，探索知识发现和信息获取新形态；可做多语言检索、跨语言理解、观点对照、资料梳理、学习路径规划等 |
| AI × 陪伴与交互 | 探索数字伙伴和人机交互；可做 AI 学习伙伴、情绪陪伴 Agent、桌面助手、互动叙事、数字桌宠及软硬一体交互方案，可结合刘看山 IP |
| AI × 出海 | 面向湾区外贸、跨境电商、品牌出海与粤港澳双城生活；可做询盘解析、客商沟通、贸易资料与单证辅助、市场情报、内容本地化、跨文化适配及跨境协作工具 |

框架、编程语言和底层大模型不限。软件、App、插件、桌面客户端、硬件及线下装置均可按对应交付规范参赛。

## 参赛流程

### 1. 完成报名

通过上方 S3 报名链接登录知乎账号，填写报名问卷，按页面要求完成信息提报。

官方手册列明的流程为：填写报名问卷 → 添加官方助手 → 加入社群 → 组建队伍 → 提报作品。

### 2. 创建或加入队伍

通过官方活动页面完成组队，遵守每队 1–5 人、每人仅加入 1 队的规则。及时维护队伍和成员信息，并由队伍统一完成最终作品提报。

队伍信息和具体操作以活动页面当前展示为准。

### 3. 开发作品

从真实用户需求出发，选择一个赛道，完成可运行、可由评委实际体验的作品。作品应说明其与知乎社区生态的契合点及场景价值。

本次活动可使用热榜、本人关注列表、知乎搜索、全网搜索、直答 Agent 等 CLI 能力，以及刘看山 IP 素材。官方平台入口：<https://developer.zhihu.com/>。

本人关注列表通过 `zhihu-cli me followees` 查询，仅返回当前 Access Secret 所属账号关注的用户，不提供关注动态流。作品需要读取其他已授权用户的关注列表时，通过[用户数据 API](user-api.md)接入；CLI 不接受 OAuth Token。

刘看山素材包：打开以下飞书附件入口下载。

- [看山三视图.zip](https://pcnsiq9mmnww.feishu.cn/wiki/W1DVwHiJSigXq1k6ys7cHTuOnBe#R8MfdezXao3bLoxYxKLclxH1nyr)
- [刘看山动态.zip](https://pcnsiq9mmnww.feishu.cn/wiki/W1DVwHiJSigXq1k6ys7cHTuOnBe#Sn41dg71To67qdxBPyMcDEX0nde)

需要使用 CLI 时，先依据当前版本的 `capabilities` 和 `--help` 确认可用命令。代码接入按对应 Reference 核对 HTTP 契约；手册中的能力介绍不等于当前 CLI 已封装所有接口。

可通过 `zhihu-cli quota`，或打开[个人中心](https://developer.zhihu.com/profile)的「用量统计」查询当前账号的实际额度和剩余次数。调用开放能力时做好缓存和请求去重，遵守调用频次、用户数据和内容使用规范。

### 4. 创建黑客松项目

作品提报入口开放后，通过官方项目提交页填写项目信息，选择一个参赛赛道，提交体验载体与产品说明计划书；其他字段以 S3 实际页面为准。

官方手册建议尽早提报项目、积累人气，并写明 12 月 5 日项目广场开始站内曝光。早期提报或占位不代表已经满足有效作品要求，最终作品仍须在截止前满足交付清单。

## 知乎账号 OAuth

网页或纯 HTML 类项目推荐接入知乎 OAuth，登录人数是人气奖评定依据之一；OAuth 并非所有作品的硬性参赛条件。

需要知乎登录、授权用户基础信息、创作列表、关注或收藏时，按[黑客松 OAuth 接入](hackathon-oauth.md)、[授权用户基础信息 API](hackathon-user-profile-api.md)和[用户数据 API](user-api.md)配置。

应用密钥和用户 Token 保留在服务端。使用 OAuth 时，回调地址应与登记值完全一致，并实际验证授权、退出、过期和失败处理。授权与 Token 交换协议见 [OAuth 应用集成](oauth.md)。

## 提交作品

在上方赛程列明的窗口内，通过官方项目提交页完成提报，每队限 1 个作品。截止时间为 12 月 7 日 10:00，截止后不接受项目文件、演示视频和计划书的修改替换。

### 必交材料

1. 可运行体验链接或可供评委完整体验的作品载体。
2. 产品说明计划书。

不同类型作品的体验载体要求：

| 作品类型 | 提交要求 |
|---|---|
| 网页 / 纯 HTML | 公网可访问、可操作的线上 Demo 链接；设有登录功能时同步提供测试账号密码，推荐接入知乎 OAuth |
| App / 插件 / 桌面客户端 | 可下载安装包或公开链接，并说明设备、系统及环境配置，确保评委能够安装并完整体验；建议配套演示视频 |
| 硬件 / 线下装置 | 在说明文档中写明完整操作流程和运行环境要求，说明评委如何完整体验；建议配套演示视频 |

硬件和装置作品的具体交付、远程体验或现场安排，手册未进一步明确时，应向官方确认。

产品说明计划书是初审重点材料，应说明：

- 核心创作思路、目标用户与真实痛点；
- 核心体验、使用步骤和运行环境；
- 整体技术实现方案；
- 使用的知乎开放能力及其在作品中的作用；
- 与知乎社区生态、参赛主题的契合度；
- 对社区用户或业务场景的实际价值。

### 选交加分材料

- GitHub 或 Gitee 开源仓库链接，展示代码结构和工程规范。
- 线上公开视频链接，展示核心功能和使用场景。

### 提交前检查

1. 体验链接、安装包或硬件体验方式可以支持评委实际完成核心流程。
2. 参赛赛道、项目信息与产品说明已完成，作品与知乎社区生态及主题相关。
3. 需要登录的网页提供可用测试账号；安装类作品提供系统和环境说明。
4. 仓库与视频链接可以被评委访问；硬件类作品操作流程完整。
5. 使用 OAuth 时，回调地址与登记值一致，授权和退出流程实际可用。
6. App Key、Access Secret、OAuth Token 等密钥未出现在源码、前端响应、日志、截图或视频中；提交的体验账号不复用个人或生产管理账号。
7. 接口失败、额度耗尽和空数据有真实的错误或降级提示。
8. 作品、素材和使用数据符合原创、授权与赛事规范，保留必要创作佐证。
9. 所有最终材料在 12 月 7 日 10:00 前提报完成，未将保存、占位或 Mock 测试写成最终交付完成。

## 原创、内容与知识产权

- 作品须为团队独立创作，禁止搬运、抄袭、外包代做和一稿多投；已在其他竞赛获奖或公开发布的项目不得参赛。应保留 AI 交互记录、设计底稿、开发日志等创作佐证。
- 作品需遵守法律法规、社区规范和 API 使用规范，禁止未经授权使用第三方素材、批量爬取和滥用用户数据。与主题或知乎社区生态无关及违规作品不参与评奖。
- 作品版权归参赛团队；知乎获得永久、非独家、免费的线上传播展示授权，用于赛事等非商业宣传并标注团队信息。后续站内落地、商用或孵化另行沟通授权。
- 比赛开放的刘看山形象仅可在比赛期间使用；赛后相关元素禁止商用，商用需联系知乎取得正式授权。
- 禁止多账号作弊、刷赞、代做、盗用项目等行为；官方手册列有取消资格、追回奖励与福利等处置规则。
- 主办方可按政策及实际情况调整赛程、宣讲和线下安排。补充说明与主赛事规则冲突时，以补充说明为准。
